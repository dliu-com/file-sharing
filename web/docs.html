How share.dliu.com is tested如何检测 share.dliu.com

Every 15 minutes, status.dliu.com visits DL Share like a friend who has not been sent a link: it never signs in and changes nothing. It opens the public pages, tries a link that doesn't exist, starts (but never finishes) the owner sign-in, and asks /health whether the link store and the sign-in settings answer.

status.dliu.com 每 15 分钟访问一次 DL Share，就像一位还没收到链接的朋友：从不登录，也不改任何内容。它打开公开页面，试一个不存在的链接，发起（但不完成）站长登录，并通过 /health 询问链接库和登录设置是否正常。

Health endpoint健康检查接口

/health answers with one word per function: pass, warn or fail. It needs no sign-in, reveals nothing private, and runs at most about once a minute however often it's asked.

/health 为每项功能给出一个结果：正常、警告或失败。它不需要登录，不透露任何私密信息，不管被请求多少次，每分钟最多真正运行一次。

Technical details技术细节: /health

GET https://share.dliu.com/health (also HEAD) returns 200 when status is pass or warn and 503 when it is fail, with Content-Type: application/health+json and Cache-Control: public, max-age=60. Other methods get 403 from CloudFront.

{
  "status": "pass",
  "time": "2026-11-03T23:00:00Z",
  "functions": [
    { "key": "links", "name": "Share links", "status": "pass" },
    { "key": "signin", "name": "Owner sign-in", "status": "warn", "output": "slow" }
  ]
}

The top-level status is the worst of the functions'. CloudFront's /health behaviour caches for 60 s with a cache key of nothing (no headers, cookies or query string) and has no origin request policy, so no cookies, Authorization header or query string reach the API, and the handler reads none. output is only ever slow, not ready, timeout, not configured or read failed. The checks run in parallel, so the answer comes within about 2 s. A check over 1000 ms is slow, except on the function's first run after a cold start, whose time is mostly Lambda start-up.

Every guest check sends no cookies, no Authorization header and no query string, doesn't follow redirects, and uses the user agent dliu-status-bot/1.0 (+https://status.dliu.com/docs). A check passes when the status matches, the Content-Type starts with the expected type (-: not checked) and the body contains the marker (for a redirect, the Location header starts with it).

Caching: HTML pages send Cache-Control: no-cache; style.css and health.md send public, max-age=0, must-revalidate, s-maxage=86400 and every deploy invalidates them. The “Link not found” page and the API send no-store.

What isn't tested不检测的内容

  • Opening real shared files and folders: that needs a real share link, and the files come from OneDrive, which the checks never call.
  • Everything the owner does after signing in: creating, renaming, changing and deleting links.
  • Finishing the Microsoft sign-in, which needs the owner's own account.
  • Removing a changed or deleted link's files from the CloudFront cache.
  • 打开真实的分享文件和文件夹：这需要真实的分享链接，而文件来自 OneDrive，检测从不访问 OneDrive。
  • 站长登录后的所有操作：创建、重命名、修改和删除链接。
  • 完成 Microsoft 登录，这需要站长自己的账户。
  • 链接修改或删除后，从 CloudFront 缓存中清除其文件。
